# t&tech 팀 업무 공유 기획안

## 서비스 목표

팀원이 오늘 할 일과 다가오는 업무를 공유하고, 일일·주간회의에서 확인한 결정과 후속 업무를 한 캘린더에서 관리한다. 개인 메모·일기 중심 화면을 팀 업무 중심으로 전환한다.

## 팀이 사용하는 흐름

1. 팀원이 견적·납품·업무협의·기타 업무를 등록하고 시작일과 마감일을 지정한다. 다른 팀원은 캘린더에서 담당자와 업무 기간을 확인한다.
2. 일일회의에서 오늘 업무, 기한 초과 업무, 막힌 일을 확인한다. 결정과 후속 업무를 기록하고 기존 업무를 연결하거나 새 업무를 만든다.
3. 주간회의에서 지난주 완료 업무와 이번 주 예정 업무를 검토한다. 다음 주로 넘기는 업무에는 담당자와 새 날짜를 지정한다.
4. 회의에서 만든 업무는 캘린더와 대시보드에 함께 표시한다. 업무 상세에서 생성 근거가 된 회의를 열 수 있다.
5. 완료한 견적에서 업체명과 비고를 가져와 납품 업무의 초안을 만든다. 날짜와 담당자를 확인한 뒤 저장한다.

## 첫 출시 범위 제안

업무 캘린더의 세부 요구는 [업무관리 캘린더 요구사항](업무관리캘린더/업무관리%20캘린더%20요구사항.md)을 참고한다.

| 영역 | 동작 |
|---|---|
| 팀 접근 | 로그인한 팀원은 팀 전체 업무를 조회하고 자기 업무를 등록·수정·삭제할 수 있다. 팀장은 팀의 모든 업무를 수정·삭제하고 담당자를 배정·변경할 수 있다. |
| 업무 | 제목, 시작일·마감일, 업무구분, 업체명, 담당자, 비고, 상태를 관리한다. 상태는 대기·진행 중·완료다. |
| 캘린더 | 업무 기간과 담당자를 월간 화면에서 확인하고, 업무를 선택하면 상세 모달에서 내용과 상태를 본다. 내 업무와 팀 전체를 전환할 수 있다. |
| 대시보드와 검색 | 오늘, 기한 초과, 이번 주, 이번 달 업무를 표시한다. 카드에서 해당 업무 목록을 열고, 목록의 업무를 선택하면 캘린더와 같은 상세 모달을 연다. 날짜 범위·업체·구분·상태·담당자로 찾는다. |
| 일일·주간회의 | 팀원이 회의 종류와 날짜, 안건, 결정 사항, 후속 업무를 남긴다. 기존 업무도 연결할 수 있다. |
| 주간보고 | 팀원은 주차별 개인 보고를 작성·제출하고, 팀장은 이를 모아 본다. 팀장은 같은 주차에 팀 보고서 한 건을 별도로 작성할 수 있다. |
| 견적에서 납품 | 완료한 견적을 바탕으로 납품 초안을 열고, 저장된 납품에서 원본 견적을 확인한다. |

사전 알림은 업무별 30일 전·7일 전·1일 전·당일 옵션과 예정·기한 초과를 보는 알림센터를 후보로 둔다. PC·모바일 푸시는 후속 범위로 둔다. AI 회의 요약이나 과거 결정 검색도 팀의 회의·업무 데이터가 연결된 뒤 우선순위를 정한다.

## 팀 권한과 주간보고

업무의 수정·삭제 권한에서 본인은 현재 담당자를 뜻하는 것으로 기획한다. 팀원이 업무를 등록하면 자신이 담당자가 된다. 다른 팀원에게 배정하거나 담당자를 바꾸는 권한은 팀장에게 있다. 상태 변경은 업무 수정 권한을 따른다. 다른 팀원은 상세를 조회할 수 있으며 API에도 같은 접근 규칙을 적용한다.

주간보고는 월요일부터 일요일까지의 개인 보고와 팀 보고를 같은 화면에서 다룬다. 개인 초안은 작성자만 볼 수 있고, 개인 보고를 제출하면 팀장이 볼 수 있다. 팀장은 개인 보고 제출 여부와 내용을 모아 보며 팀 보고서 한 건을 별도로 작성할 수 있다. 게시된 팀 보고서는 팀원 전체가 본다. 첫 출시에서는 제출·게시한 보고서와 제출 시 저장한 업무 내역을 고정한다.

## UI·UX 방향

홈에서 워크스페이스를 누르면 로그인한 사용자는 목록으로 이동하고, 로그인 전이라면 로그인 후 목록으로 이동한다. 목록에서 팀 또는 개인 워크스페이스를 열면 월간 업무 캘린더가 열린다. 팀 공간은 담당자별 공유 업무를, 개인 공간은 본인에게만 보이는 업무를 표시한다. 팀장도 다른 사람의 개인 공간을 조회할 수 없으며 개인 업무는 팀 집계와 보고 자료에서 제외한다.

팀 워크스페이스의 보고서 메뉴에는 일일회의 보고서, 주간회의 보고서, 주간 업무보고를 둔다. 일일회의는 날짜별, 주간회의는 월요일 기준으로 안건·결정·후속 업무를 기록한다. 팀원이 조회·작성할 수 있고 수정은 작성자와 팀장에게 허용한다. 기존 개인 제출·팀 보고는 주간 업무보고에서 사용한다.

팀 업무 협업 도구에는 로열 블루 `#1d4ed8`과 밝은 캔버스를 적용한다. 포털과 영업 캘린더의 레이아웃, 배지와 확장 화면 규격은 [DESIGN.md](DESIGN.md)를 따른다.

업무 유형과 상태는 각각 색과 텍스트로 구분한다. 기한 초과는 별도의 경고 표시로 드러낸다. PC는 대시보드와 월간 캘린더에서 동일한 업무 상세 모달을 열고, 모바일은 선택 날짜의 업무 목록을 보여준 뒤 상세와 등록을 전체 화면에서 제공한다.

## 기술 결정

프론트는 React/Vite, 백엔드는 Next.js Route Handlers, 관계형 DB는 SQL Server Express를 사용한다.

SQL Server DB는 기존 개인 기록을 이관하지 않고 시작했다. 다음으로 팀 업무의 접근 제어, 등록·조회 API와 캘린더 화면을 연결한다.

## 구현 순서와 완료 기준

1. **팀 접근** — 팀장 초기 등록, 팀원 초대·수락, 로그인·로그아웃 순서로 연결한다. 팀장·팀원이 자기 팀에 팀원을 초대할 수 있고(2026-11-24 결정, 팀장 자리 초대는 관리자만), 만료되거나 사용한 초대는 수락할 수 없다. 초대한 팀원이 참여하고, 로그아웃 이후나 소속되지 않은 팀에 대한 API 요청이 차단되는지 검증한다.
2. **업무 공유·캘린더** — 담당자와 팀장이 업무를 수정·삭제하고, 팀장이 담당자를 배정한다. 다른 팀원은 캘린더에서 기간과 담당자, 상세 모달을 확인한다. 월 경계를 넘는 업무가 표시되고, 권한 없는 변경이 API에서 차단되는지 검증한다. 완료한 견적에서 납품을 등록하면 원본과 연결된다.
3. **대시보드** — 오늘·기한 초과·주간·월간 카드에서 업무 목록과 공통 상세를 연다. 담당자·기간 등으로 검색하고, 업무 수정이 캘린더와 대시보드 양쪽에 반영되는지 검증한다.
4. **주간보고** — 팀원은 개인 보고를 제출하고 팀장은 제출 현황을 확인하거나 주차별 팀 보고서를 작성한다. 개인 보고가 없는 주차에도 팀 보고서를 작성할 수 있는지 검증한다.
5. **최종 홈 화면** — 앞 단계에서 구현한 기능과 실제 업무 흐름을 바탕으로 첫 화면에 보여줄 정보, 이동 경로, PC·모바일 배치를 결정한다. 현재 예시 대시보드는 참고용 시안이다.

일일·주간회의 보고서에는 후속 업무를 텍스트로 남긴다. 회의에서 캘린더 업무를 생성하고 회의 상세와 업무 상세를 연결하는 흐름, 사전 알림과 AI는 이후 범위다.

## 조직·권한 결정 (2026-11-23, 사용하며 조정)

와이어프레임(docs/design, docs/업무관리캘린더) 구현을 위해 아래 안으로 확정했다. 테스트하면서 바꿀 수 있다.

- **조직:** 7개 팀이 있으며, 대표와 본부장은 각 1명이다. 대표는 회사 소속이다. 본부장은 회사 또는 한 팀을 소속으로 선택하고, 별도로 지정된 한 팀의 팀장을 겸임할 수 있다.
- **권한:** 회사 관리자는 전사 조회·결재·조직 관리를 맡는다. 팀장은 맡은 팀의 초대·업무 배정·수정·결재를 한다. 팀원은 소속 팀 업무를 보고 본인 업무와 보고를 작성하며, 자기 팀에 팀원을 초대한다.
- **계정:** 가입은 초대가 정한 소속과 직급으로 진행한다. 내 설정에서는 이름과 비밀번호를 바꾼다. 다른 회사 관리자가 조직 변경을 처리하고 이력을 남긴다. [권한 세부 기준](PERMISSIONS.md)
- **팀 유형별 업무 구분:** 화면 표기는 기술(기술영업 3개 팀, 코드 SALES)·개발(솔루션개발 2개 팀, DEV)·연구(기업부설연구소, TECH)·경영(경영지원팀, SUPPORT)이다. 기술은 견적·납품·업무협의·기타, 개발·연구는 개발·테스트·현장지원·회의·기타, 경영은 구매·결재·인사·회계·기타를 쓴다. 견적→납품과 업체 관리는 기술(기술영업) 유형만 쓴다.
- **초대:** 팀 공용 고정 링크는 쓰지 않는다. 이메일별 1회용 링크, 유효기간 7일, 초대할 때 팀(관리자는 역할도)을 지정한다. 초대한 사람을 기록하고, 팀원은 다른 사람이 보낸 대기 중 초대를 덮어쓰지 못한다. 재발송하면 이전 링크는 무효다. 메일 서버가 생기기 전까지 링크 복사로 전달한다.
- **보고:** 팀원 주간보고는 팀장에게 제출하고, 팀장에게는 작성 중·제출·미제출 상태만 보이며 초안 내용은 비공개다. 팀장이 작성한 팀 주간보고는 관리자가 전사 현황으로 모아 본다.
- **개인 공간 메모:** 소유자가 있는 개인 메모를 새로 만든다. 기존 나의 하루 기록은 자동으로 옮기지 않는다.
- **외부 연동:** 카카오 공유·알림톡은 하지 않는다(링크 복사, 앱 내 알림으로 대체). ERP 버튼은 연동 준비 중으로 비활성, ERP 자동 전송 안내는 숨긴다. 푸시는 앱 내 알림센터를 먼저 하고 HTTPS 배포 뒤 웹 푸시를 추가한다. 팀 채팅은 이후 단계에서 팀마다 채널 1개로 만든다.
- **로고:** 로고 파일을 받기 전까지 텍스트 로고를 쓴다.
- **기존 데이터:** 업무·회의·보고는 당시 팀에 남는다. 회사 계정과 팀장 배정 이전은 권한 문서를 따른다.
- **구현 순서:** 조직 기반 → 메인 캘린더·워크스페이스(와이어프레임 배치, 팀 유형별 구분) → 업무 상세 → 회의·보고서 → 좁은 화면 배치 → 알림센터·채팅. 2026-11-23 기준 조직 기반과 메인 캘린더·워크스페이스까지 구현했다([HANDOFF.md](HANDOFF.md)).

## 확인이 필요한 제품 결정

- 제출한 주간보고를 되돌리거나 정정하는 절차는 사용 흐름을 확인한 뒤 정한다.
- 기존 개인 메모·일기를 별도로 보관할지, 기존 할 일·약속 중 어떤 데이터를 팀 업무로 옮길지.

기존 개인 데이터가 있다면 팀 공유 대상으로 자동 전환하지 않는다. 실제 구현 상태와 이전 개발 이력은 [HANDOFF.md](HANDOFF.md)를 참고한다.
