## 기존 기능과 기술 부채

- **업무 조회가 전체 조회**(`scope=all`)다. 데이터가 쌓이면 기간별로 나눠 받도록 API와 화면을 바꿔야 한다(업체 이력·지난 달 캘린더 고려).
- **기존 '나의 하루' 데이터 보관**은 미정이다. 전용 화면·API를 제거했고 기존 데이터베이스의 테이블은 보관하고 있다.
- **반복 설정은 알림 표시에만 쓰인다.** 반복 업무를 자동으로 만들지 않는다.
- **업체 마스터가 없다.** 업체 주소·연락처·ERP 연결은 업체 테이블이 필요하다. 지금 업체 관리는 업무에 적힌 업체명을 모아 보여준다.
- **조직 마이그레이션 검증이 저장소 밖에 있다.** 예전 구조 DB로 마이그레이션을 확인하는 스크립트를 `scripts/`에 정식으로 넣어야 한다.
- **브라우저 검증 도구**: Playwright가 저장소 의존성에 없어 `PLAYWRIGHT_MODULE_PATH`로 따로 지정해야 한다.
- 자정이 지나도 화면 날짜가 자동으로 바뀌지 않고, 동시에 고치면 마지막 저장이 반영된다.
- 채팅 화면(`/#chat`)은 예시 데이터로 동작한다.

## 협업 기능 제안 (2026-11-24)

사용자와 논의한 추가 후보다. 아직 착수하지 않았고, 우선순위는 사용자 확정 전 제안이다. 위 단계에 이미 있는 항목은 "(계획 있음)"으로 표시했다.

**추천 착수 순서:** 업무 댓글·@멘션과 알림 종류 확대 → 회의 후속 업무 연결. 알림 드롭다운과 변경 이력 구조가 이미 있어 비교적 빨리 붙일 수 있다.

### 1순위: 팀원 간 소통

| 기능 | 내용 | 필요한 것 |
|---|---|---|
| 업무 댓글·@멘션 | 업무 상세에 댓글, @이름으로 부르면 그 사람에게 알림 | 댓글 테이블, 멘션 파싱, 알림 연결 |
| 공동 협업자 (계획 있음) | 담당자 외 함께하는 사람 추가 | 3단계 협업자 권한 결정 |
| 알림 종류 확대 | 지금은 "N일 전" 알림뿐. 업무 배정·상태 변경·멘션·결재 요청 알림 추가 | 6단계 알림 테이블·읽음 처리 |

### 2순위: 회의와 업무 연결 (계획 있음, 4단계)

- 회의 후속 조치를 그 자리에서 캘린더 업무로 등록·연결
- 회의별 후속 업무 진행률 ("6건 중 4건 완료")
- 팀장의 팀원 주간보고 현황 (작성 중·제출·미제출)

### 3순위: 영업팀용

| 기능 | 내용 |
|---|---|
| 업체 이력 타임라인 | 업체 관리에서 업체별 업무·회의·첨부를 시간순으로 보여줌. 담당자 인수인계용 |
| 견적→납품 흐름 표시 | 업체별 "진행 중 견적 N건, 납품 대기 N건" (견적 완료 → 납품 등록은 이미 있음) |
| 외근·휴가 일정 공유 | 팀 캘린더에 부재 일정 표시, 업무 배정 시 참고 |

### 4순위: 관리자·대표용

- 전사 현황 대시보드 (계획 있음): 팀별 지연 업무, 이번 주 완료율, 결재 대기
- 활동 기록: 누가 무엇을 바꿨는지 흐름. 변경 이력 데이터는 이미 있어 화면만 필요

### 그 외

- 매주·매월 반복 업무 자동 등록

## AI 비서 (RAG·벡터DB) 제안 (2026-11-24)

사용자와 논의한 AI 비서 기능 후보다. 아직 착수하지 않았다. 구성 요소(FastAPI `ai`, Ollama, 임베딩 `bge-m3`, Qdrant)는 docker compose에 있으나 팀 업무·회의 데이터와는 연결되지 않았다. 원칙은 [AGENTS.md](../AGENTS.md)의 AI 항목(원문·인덱스 분리, 사실·제안 구분, 실제 출처, 수정 전 버전·삭제 기록 제외)을 따른다.

**먼저 정할 것:** 생성 모델을 로컬 Ollama로 둘지 외부 API(Claude 등)를 쓸지. 외부 API는 답변 품질이 높지만 고객사 정보가 회사 밖으로 나간다. 이 결정에 따라 인덱싱·전송 범위 설계가 달라진다.

### 1순위: 검색하고 묻기

| 기능 | 예시 질문 | 근거 데이터 |
|---|---|---|
| 과거 결정 찾기 | "삼성전자 납품 일정 언제로 정했었지?" | 회의 결정 사항, 업무 메모 |
| 업체 이력 요약 | "LG화학 건 지금까지 어떻게 진행됐어?" | 업체별 업무·회의·첨부 |
| 업무 인수인계 | "최현우가 맡던 업무 정리해줘" | 담당 업무, 변경 이력, 메모 |
| 첨부 문서 검색 | "견적서에 단가 얼마로 넣었더라?" | 업무 첨부 PDF 본문 |

답변마다 근거 원문(예: `TSK-0085`, `2026-11-12 일일회의`) 링크를 붙이고 누르면 해당 업무·회의로 이동한다.

### 2순위: 작성 도와주기

- 회의록 초안: 그날 연결된 업무로 안건·후속 조치 초안
- 주간보고 초안: 이번 주 완료·진행 업무로 "이번 주 한 일 / 다음 주 계획"
- 업무 등록 도우미: "다음 주 화요일 현대차 견적 미팅" → 날짜·업체·구분을 채운 등록 화면(저장은 사람이)

### 3순위: 먼저 알려주기

- 오늘의 브리핑: 포털에 "오늘 마감 2건, 지연 1건, 내일 미팅 준비 필요"
- 팀장용 위험 신호: 지연이 잦은 업체·업무, 오래 멈춘 업무
- 비슷한 업무 찾기: 새 업무 등록 시 과거 유사 건 안내

### 설계 원칙

1. **권한 그대로:** 질문한 사람이 볼 수 있는 것만 검색한다(팀원은 자기 팀, 개인 캘린더 업무는 본인만, 대표·본부장은 전 팀 조회). Qdrant 포인트에 팀 ID·개인 소유자 ID·원본 종류를 넣고 검색 시 필터한다.
2. **원문은 SQL Server, 벡터는 재생성 가능한 사본:** 저장 후 인덱스 갱신은 별도로 처리하고, AI 장애가 업무 저장·조회에 영향을 주지 않는다.
3. **최신본만 근거:** 수정 시 이전 벡터를 지우고 다시 넣고, 삭제된 업무는 인덱스에서도 뺀다.
4. **사실과 제안 구분:** 근거가 있는 사실("회의에서 12/5로 정했습니다 [근거]")과 추정·제안("지연 가능성이 있어 보입니다")을 화면에서 다르게 표시한다.
5. **AI는 읽고 제안만:** 업무 생성·상태 변경은 항상 사람이 확인하고 실행한다.
