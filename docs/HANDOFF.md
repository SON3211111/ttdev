# t&tech 인수인계

최종 갱신: 2026-11-25 (Asia/Seoul)

- 2026-11-25 본부장 행을 팀원 행과 통일: 직급·팀 선택·저장을 같은 줄에 두고 ‘소속팀’·‘담당 팀’ 문구와 두 번째 팀 선택칸을 제거했다. 남은 팀 선택칸에서 회사 소속 또는 팀을 고르며, 기존 겸임 담당 팀은 저장 요청에 유지한다. 프론트 lint·빌드 통과. 5174 헤드리스 Edge 모의 대표 세션으로 1440px·390px 정렬, 팀 목록 지연 후 소속 복원, 회사 소속 저장 시 담당 팀 유지 요청 확인.

- 2026-11-25 대표 화면의 본부장 소속 편집: 본부장 행에 ‘소속팀’과 ‘담당 팀’ 이름을 각각 선택칸 왼쪽에 붙이고 선택칸의 위치와 너비를 맞췄다. 팀 목록이 나중에 도착해도 저장된 선택값을 복원하고 로드 중에는 저장 버튼을 비활성화한다. 프론트 lint·빌드 통과. 5174 헤드리스 Edge의 모의 대표 세션에서 팀 응답을 지연해 저장값 복원 확인, 1440px·390px 정렬 확인, 회사 소속 저장 요청이 기존 담당 팀을 유지하는지 확인했다.

- 2026-11-25 조직 변경 이력 재검증: 전체 변경 `d8ca307`을 `origin/main`에 푸시한 뒤 격리 SQL Server에서 수정된 소스로 팀 API 통합 검증을 한 번 실행했다. 17개 통과. 관리자 직급 변경, 팀원 내보내기, 본부장 자기 소속 변경이 이력 API에 기록되며, 본부장 자기 변경은 처리자와 대상이 같고 변경 전후 소속 값이 일치했다. 검증 DB는 정리했다.

- 2026-11-25 인사관리 사용자 행 정렬: 대표 조회 행, 본부장 자기 행, 일반 편집 행의 직급·소속 위치를 같은 그리드로 맞췄다. ‘내 계정’ 표시는 사용자 이름 아래로 옮겼다. 프론트 lint·빌드 통과. 5174의 헤드리스 Edge에서 모의 본부장 세션으로 1440px·390px 모두 직급과 소속의 가로 위치가 일치하고 본부장 자기 행에 저장 버튼이 표시되는 것을 확인했다.

- 2026-11-25 인사관리 본부장 행 정렬 및 대표 계정 보호: 소속팀 선택 위 문구를 제거하고 본부장 자기 행의 선택과 저장을 같은 줄에 배치했다. 본부장에게 대표 행의 직급과 계정 상태는 조회 전용으로 표시하고 직접 API 변경 요청도 403 `HIGHER_RANK`로 차단한다. 직접 검증: 백엔드 단위 테스트 11개, 프론트 lint·빌드, Docker 백엔드 빌드, 격리 SQL Server 팀 API 통합 점검 17개 통과. 5174 갱신 후 사용자 관리 모듈·팀 세션 HTTP 200 확인. 브라우저에서 실제 배치는 확인하지 않았다.

- 2026-11-25 본부장 소속팀: 인사관리 사용자 표의 본부장 자기 계정에서 소속팀을 저장하거나 회사 소속으로 돌릴 수 있다. 다른 회사 관리자는 본부장 행에서 소속팀과 담당 팀을 별도로 설정한다. 자기 소속 변경은 조직 이력에 남고 담당 팀과 관리 권한에는 영향이 없다. 겸임 중 기본 팀 공간은 담당 팀으로 열린다. 직접 검증: 백엔드 단위 테스트 10개, 격리 SQL Server 팀 API 통합 점검 17개, 프론트 lint·빌드와 Docker 백엔드 빌드 통과. 5174 데모 갱신 후 홈·사용자 관리 모듈·팀 세션 HTTP 200 확인. 브라우저에서 폼을 직접 저장하는 동작은 확인하지 않았다.

- 2026-11-25 인사관리 사용자 표: 본부장으로 로그인해 자기 행을 볼 때도 다른 행과 동일한 계정 상태 열에 ‘활성’ 또는 ‘비활성’이 표시되도록 했다. 다른 계정의 상태 변경 버튼은 상태 아래에 두고 열 너비와 줄바꿈을 통일했다. 프론트 lint·빌드 통과. 5174 홈과 수정된 사용자 관리 모듈 HTTP 200 확인. 헤드리스 Edge 테스트에서 대상 표가 렌더링되지 않아 실제 브라우저 배치는 확인하지 못했다.

- 2026-11-25 팀원 내보내기: 팀장(겸임 본부장 포함)이 설정에서 담당 팀의 활성 프로 계정을 선택하고 확인하면 소속이 해제된다. 계정과 개인 캘린더는 유지되고, 기존 업무·보고는 원래 팀에 남는다. 조직 이력에 처리자와 변경을 남기며 회사 관리자는 조직 관리에서 소속을 다시 지정할 수 있다. 직접 검증: 백엔드 단위 테스트 9개, 프론트 lint·빌드, Docker 백엔드 빌드, 격리 SQL Server에서 팀 API 통합 점검 16개 통과(타 팀·본인 차단, 기록 보존, 개인 접근, 조직 이력, 재배정 포함). 5174 데모 백엔드 갱신 후 홈·팀 세션 HTTP 200 확인. 5173 백엔드는 기존 컨테이너로 실행 중이다.

- 2026-11-25 데모 접속 복구: 5174 포트에 프론트 서버가 떠 있지 않아 `frontend`에서 Vite를 다시 실행했다. `API_TARGET=http://127.0.0.1:18160`으로 기존 데모 백엔드를 연결했다. 5174의 홈, 프론트 진입 모듈, 프록시를 거친 팀 세션 API가 모두 HTTP 200을 반환했다. 개발 서버가 내려가면 같은 설정으로 다시 실행한다.

## 기획 전환

- 새 팀 업무 서비스 이름은 `t&tech`로 정했다. 새 UI에서 이 이름을 적용한다.

- 팀 업무 공유와 일일·주간회의를 업무관리 캘린더에 연결하는 방향으로 전환한다. 새 범위와 구현 순서 초안은 [PROJECT_PLAN.md](PROJECT_PLAN.md)에 있다.
- 팀원은 자기 업무를 등록·수정하고 팀 전체 업무의 시작일·마감일과 담당자를 캘린더에서 확인한다. 캘린더와 대시보드에서 같은 업무 상세 모달을 열도록 기획서와 업무관리 캘린더 요구사항에 반영했다.
- 새 팀 업무 화면의 대표색은 연두색으로 정했다. 화면 적용 방향은 기획서의 UI·UX 방향에 있다.
- 업무 배정·담당자 변경은 팀장, 수정·삭제는 팀장과 본인에게 허용하는 방향을 반영했다. 본인은 현재 담당자로 해석했다. 업무 상태는 대기·진행 중·완료다. 주간보고는 팀원별 제출·팀장 모아보기와 팀장의 주차별 팀 보고서 작성을 지원하는 기획이다.
- Compose는 Next.js와 SQL Server Express를 사용한다. 팀 권한을 구현했고 회의 기록은 후속 범위다.
- 새 SQL Server 볼륨을 사용한다. 기존 MySQL 데이터는 이관하지 않았으며, 사용자 요청으로 `dev-mysql` 컨테이너, `dev_mysql_data` 볼륨, Spring Boot `backend/` 디렉터리를 삭제했다.
- 이 PC에서 남은 MySQL Docker 이미지, Windows MySQL 설정·데이터 폴더, Gradle MySQL 커넥터 캐시와 프로젝트의 구 MySQL 환경변수를 삭제했다.

## 제거된 개인 기능 이력

서비스명을 **나의 하루**로 변경했다. 화면의 이름과 현재 프로젝트 문서에 반영했다.

로컬 단일 사용자 MVP에서 메모·일기, 약속, 통합 캘린더, 할 일 관리와 대시보드를 구현했다. 팀 전환 후 구현 순서는 새 기획서를 따른다.

| 화면 | 사용 흐름 |
|---|---|
| 홈 | 오늘 날짜와 빠른 메모·일기 작성. **앞으로 7일**에는 서울 기준 오늘~6일 후의 예정 약속과 해당 기간에 마감하는 미완료 할 일을 날짜순으로 표시. 기한이 지난 할 일은 건수로 표시 |
| 기록 | 상단 **기록**에서 전체 메모·일기 목록을 열고 종류별로 조회. 상세에서 원문·수정·삭제 |
| 캘린더 | 날짜 칸에서 마감일 기준으로 미완료 `할 일`과 `완료한 일` 건수를 구분. 날짜 팝업에서 메모·일기·약속·할 일과 상태를 확인. 약속 추가·수정·삭제, 오늘·과거 날짜의 메모·일기 작성, 할 일 상세 이동 |
| 일정 관리 | 할 일 등록·수정·삭제, 상태별 목록, 마감일과 변경 이력. 상세의 **하기 전 / 하는 중 / 완료** 버튼으로 원하는 상태로 이동. `#tasks`에서 새로고침해도 일정 관리 화면을 유지하며 브라우저 뒤로가기·앞으로가기를 지원 |
| 내 일정 한눈에 | 일정 관리 제목 바로 아래에 표시. **내 일정, 지금은** 진행 상태 도넛, **남은 일정**, **지난 일정** 순서. 두 주간 그래프는 제목 바로 아래에 합계를 표시 |
| 물어보기 | 홈의 **나의 하루에 물어보기** 질문 미리보기. 답변과 출처 연결은 후속 작업 |

### 당시 데이터와 변경 규칙

- 메모·일기는 서울 기준 오늘과 과거 기록을 저장한다. 날짜·제목·본문 변경 시 원문 버전이 증가하고 검색 상태가 PENDING으로 바뀐다. 목록은 기록 날짜·작성 시각·ID 내림차순이며 일반 키워드 검색은 제외됐다.
- 약속은 과거·미래 날짜를 모두 지원하고 시간·장소·메모는 선택이다. 예정·완료·취소 상태를 사용자 입력으로 변경한다. 홈의 약속 조회는 7일 동안의 예정 상태만 대상으로 한다.
- 할 일은 마감일이 지난 미완료 상태에서 지연으로 집계한다. 마감일이 있는 할 일은 모든 상태가 캘린더에 표시된다. 완료에서 다른 상태로 바꾸면 완료 시각을 비우며, 같은 상태를 다시 요청하면 변경 이력을 추가하지 않는다.
- 원문 저장·조회는 AI의 실행 상태와 독립적이다. SQL Server는 원본 저장소이고 Qdrant는 향후 재생성할 수 있는 인덱스로 사용한다.
- Next.js가 SQL Server의 `appdb`에 `records`, `schedules`, `tasks`, `task_transitions` 초기 스키마를 적용한다.

### 스택 전환 당시 검증

- SQL Server가 Express Edition으로 기동했고 Next.js와 SQL Server의 준비 상태를 확인했다.
- Vite 프록시를 통해 한글 기록 등록·수정·삭제, 약속 시간과 캘린더 조회, 할 일 상태 변경·중복 완료·이력·대시보드 집계를 검증했다.
- AI가 중지된 상태에서 약속 저장·조회가 동작했다. SQL Server와 Next.js를 재시작한 뒤에도 약속 원문·시간·UTC 시각이 유지됐고 검증 데이터는 정리했다.
- Next.js 빌드와 단위 테스트 2건, 프론트 lint·build를 통과했다.

## 전환 전 검증 이력
- 사용자 요청으로 `docker compose stop`을 실행했다. `docker compose ps -a`에서 백엔드와 MySQL을 포함한 6개 컨테이너가 모두 `Exited` 상태인 것을 확인했다.
- 2026-11-20 Docker 점검에서 프론트 Vite가 먼저 기동해 Spring Boot가 포트를 열기 전 API 요청에 `ECONNREFUSED`가 발생한 것을 로그 시각으로 확인했다. 기동 완료 후 6개 컨테이너가 실행 중이고 MySQL은 `healthy`였다. Flyway 마이그레이션 3개 검증을 통과했으며 기록·약속·할 일·대시보드 조회는 백엔드 직접 및 프론트 프록시 경유 모두 HTTP 200을 반환했다. FastAPI, Qdrant, Ollama 상태 요청과 `docker compose config --quiet`도 통과했다. 부팅 순서 개선이 필요하면 백엔드 준비 상태를 확인한 뒤 프론트를 시작하도록 Compose를 조정한다.

- 주간 그래프 제목을 **남은 일정**, **지난 일정**으로 변경한 뒤 프론트 lint와 build를 통과했다.

- 포트 변경 후 현재 상태를 재확인했다. 6개 컨테이너가 실행 중이고 MySQL은 `healthy`였다. 프론트 홈, 프론트 경유 및 백엔드 직접 기록 조회, FastAPI `/health`, Qdrant `/readyz`, Ollama `/api/tags`가 모두 HTTP 200을 반환했다.

- Windows TCP 예약 범위 `7945–8044`, `8054–8153`에 포함된 AI·백엔드 호스트 포트 `8000`, `8080`을 각각 `18000`, `18080`으로 변경했다. Compose 내부 포트는 AI `8000`, 백엔드 `8080`이다. `docker compose config --quiet`와 `docker compose up -d`가 성공했고 6개 컨테이너의 실행 및 MySQL `healthy`를 확인했다. 프론트 홈, 프론트 경유 및 백엔드 직접 기록 조회, FastAPI `/health`, Qdrant `/readyz`는 HTTP 200을 반환했다.

- 홈 로고의 아이콘 안에 있던 글자를 제거했다.

- 서비스명 변경 후 프론트 lint와 build, `git diff --check`를 통과했다.

- 리뷰 준비로 일기 저장 주석을 다듬고 Spring Boot 진입점의 중복 주석을 정리했다. 주석과 문서 변경을 diff로 확인했다.
