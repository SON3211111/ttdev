# 나의 하루 인수인계

최종 갱신: 2026-11-23 (Asia/Seoul)

## 기획 전환

- 새 팀 업무 서비스 이름은 `t&tech`로 정했다. 새 UI에서 이 이름을 적용한다.

- 팀 업무 공유와 일일·주간회의를 업무관리 캘린더에 연결하는 방향으로 전환한다. 새 범위와 구현 순서 초안은 [PROJECT_PLAN.md](PROJECT_PLAN.md)에 있다.
- 팀원은 자기 업무를 등록·수정하고 팀 전체 업무의 시작일·마감일과 담당자를 캘린더에서 확인한다. 캘린더와 대시보드에서 같은 업무 상세 모달을 열도록 기획서와 업무관리 캘린더 요구사항에 반영했다.
- 새 팀 업무 화면의 대표색은 연두색으로 정했다. 화면 적용 방향은 기획서의 UI·UX 방향에 있다.
- 업무 배정·담당자 변경은 팀장, 수정·삭제는 팀장과 본인에게 허용하는 방향을 반영했다. 본인은 현재 담당자로 해석했다. 업무 상태는 대기·진행 중·완료다. 주간보고는 팀원별 제출·팀장 모아보기와 팀장의 주차별 팀 보고서 작성을 지원하는 기획이다.
- Compose는 Next.js와 SQL Server Express를 사용한다. 팀 권한을 구현했고 회의 기록은 후속 범위다.
- 새 SQL Server 볼륨을 사용한다. 기존 MySQL 데이터는 이관하지 않았으며, 사용자 요청으로 `dev-mysql` 컨테이너, `dev_mysql_data` 볼륨, Spring Boot `backend/` 디렉터리를 삭제했다.
- 이 PC에서 남은 MySQL Docker 이미지, Windows MySQL 설정·데이터 폴더, Gradle MySQL 커넥터 캐시와 프로젝트의 구 MySQL 환경변수를 삭제했다.

- 2026-11-23 팀장 부서별 1명: 팀장 직급과 팀장 권한을 하나로 묶어 부서마다 1명으로 했다. 팀장으로 초대받으면 직급이 팀장으로 고정되고, 팀원으로 초대받으면 팀장을 고를 수 없다(400 `LEAD_TITLE`, 초대 미소모). 관리자가 팀장 권한을 주면 직급도 팀장이 되고 기존 팀장은 팀원 권한·프로가 된다. 처음 설정에서 대표·본부장·프로를 고르면 팀장 권한 없이 관리자다. 초대 정보 API(`GET /api/team/auth/invite?token=`)로 가입 화면에 "OO팀 · 팀장/팀원으로 초대되었습니다"를 보여준다. 마이그레이션은 어긋난 데이터를 맞추고 부서별 고유 인덱스(`team_users_one_lead_title`)를 건다. 검증: `verify-team.mjs` 15개 PASS, Edge `verify-team-ui.cjs` PASS(팀장 초대 직급 고정·팀원 초대 팀장 비활성 포함), 예전 구조 DB 마이그레이션 점검 PASS, 단위 테스트·lint·build 통과. 로컬 Compose 백엔드에 적용했다.
- 2026-11-23 대표·본부장 1명 제한: 대표와 본부장은 회사 전체에 각각 1명만 둔다. 가입(초대 수락)과 관리자의 직급 변경에서 이미 있으면 409 `TITLE_TAKEN`으로 거절하고(실패한 가입은 초대를 소모하지 않음), DB 필터 고유 인덱스로 동시 가입도 막는다. 기존 중복은 마이그레이션에서 먼저 가입한 1명만 남기고 프로로 바꾼다. 세션 응답의 `takenTitles`로 가입 화면에서 "대표 (이미 있음)"처럼 비활성 표시하고, 조직 관리 직급 선택도 이미 있는 사람의 이름과 함께 비활성 표시한다. 검증: `verify-team.mjs` 14개 PASS(1명 제한 추가), Edge `verify-team-ui.cjs` PASS, 가입 화면 직급 선택 비활성 표시를 Edge로 확인, 단위 테스트·lint·build 통과. 로컬 Compose 백엔드에 적용했다.
- 2026-11-23 관리자 겸직과 직급 선택:
  - 관리자를 별도 계정에서 권한(`is_admin`)으로 바꿨다. 처음 설치하면 첫 사용자가 소속 팀과 직급을 골라 그 팀의 팀장 겸 관리자가 된다. 마이그레이션은 예전 ADMIN 역할 계정을 기술영업 1팀 소속 관리자로 바꾸고, 관리자가 없으면 기존 팀장에게 권한을 준다. 기존 설치용 '관리자 계정 만들기'는 없앴다.
  - 직급(`title`: 대표·본부장·팀장·프로)은 가입할 때 본인이 고르는 표시용이다. 업무 권한(팀장)과 별개이며, 대표·본부장과 관리자는 다른 팀을 `?team=`으로 읽기 전용 조회한다. 관리자는 조직 관리에서 팀·팀장 권한·직급·관리자 권한을 바꾸고, 마지막 관리자는 권한을 회수할 수 없다.
  - 화면: 워크스페이스에 전체 팀 현황(팀별 팀장·인원·오늘·지연, 보기/팀장 초대), 사이드바 팀 공간 선택(내 팀 / 다른 팀 조회 전용), 다른 팀 읽기 전용 표시와 "내 팀으로 돌아가기". 처음 설정·초대 수락에 직급(처음 설정은 소속 팀도) 선택을 넣었다. 점검 중 팀 현황(팀장·인원 숫자)을 로그인 때만 읽던 문제를 찾아 화면 이동 때마다 다시 읽게 했다.
  - 검증: 단위 테스트 4개, lint·build 통과. 새 격리 DB에서 `verify-team.mjs` 13개 PASS(관리자 겸 팀장, 직급 기반 조회 범위, 마지막 관리자 보호 추가), Edge PC·모바일 `verify-team-ui.cjs` PASS(처음 설정·직급 선택·전체 팀 현황·사이드바 팀 전환·읽기 전용). 예전 구조 DB에 기존 팀장·팀원을 넣고 새 백엔드를 붙여, 기존 팀장의 관리자 권한·직급 이전·로그인·다른 팀 조회·초대와 재시작 안전성을 확인했다. 로컬 Compose 백엔드에 적용했다(기존 팀장 → 기술영업 1팀 팀장 (관리자)). 검증 DB는 삭제했다.
  - 남은 결정: 와이어프레임의 팀 공용 고정 초대 링크(A안: 재발급 등 안전장치와 함께)는 아직 정하지 않았다.
- 2026-11-23 초대 화면 정리: 팀장의 워크스페이스 화면 "새 팀원 초대"는 설정으로 이동하지 않고 그 자리에서 초대 칸을 연다(와이어프레임 위치). 링크를 만들면 초대 수락 대기 목록이 바로 갱신된다. 설정 화면은 팀원 초대 → 초대 대기 순서이고, 관리자 계정 만들기는 관리자가 없는 기존 설치에서만 맨 아래에 접힌 "기존 데이터 이전용" 항목으로 보인다. 관리자가 없는 기존 설치 상태의 격리 DB에서 Edge로 확인했고, 새 설치 기준 `verify-team.mjs` 12개와 Edge `verify-team-ui.cjs`(새 팀원 초대 버튼 흐름으로 변경)가 통과했다. 와이어프레임의 팀 공용 고정 초대 링크와 관리자 겸직 여부는 결정 대기 중이다.
- 2026-11-23 초대 링크 문제 수정: 사용자는 있지만 관리자가 없는 기존 설치(로컬 DB 상태)에서 로그인 화면 대신 관리자 설정 화면이 떠서 기존 팀장이 로그인하지 못했고, 그래서 초대 링크를 만들 화면에 들어갈 수 없었다. 세션 응답을 `setupRequired`(사용자 0명일 때만)와 `adminMissing`(관리자 없음)으로 나눠, 기존 설치에서는 로그인 화면을 보여주고 팀장이 설정에서 관리자 계정을 만들게 했다. 같은 상태의 격리 DB에서 팀장 로그인 → 설정 → 초대 링크 생성(201)과 초대 대기 목록 표시를 Edge로 재현·확인했고, 기존 설치 흐름 점검, `verify-team.mjs` 12개, Edge `verify-team-ui.cjs`, 단위 테스트, lint·build가 통과했다. 로컬 Compose 백엔드에 적용했다(`setupRequired: false`, `adminMissing: true`).

## 데이터와 변경 규칙

- 메모·일기는 서울 기준 오늘과 과거 기록을 저장한다. 날짜·제목·본문 변경 시 원문 버전이 증가하고 검색 상태가 PENDING으로 바뀐다. 목록은 기록 날짜·작성 시각·ID 내림차순이며 일반 키워드 검색은 제외됐다.
- 약속은 과거·미래 날짜를 모두 지원하고 시간·장소·메모는 선택이다. 예정·완료·취소 상태를 사용자 입력으로 변경한다. 홈의 약속 조회는 7일 동안의 예정 상태만 대상으로 한다.
- 할 일은 마감일이 지난 미완료 상태에서 지연으로 집계한다. 마감일이 있는 할 일은 모든 상태가 캘린더에 표시된다. 완료에서 다른 상태로 바꾸면 완료 시각을 비우며, 같은 상태를 다시 요청하면 변경 이력을 추가하지 않는다.
- 원문 저장·조회는 AI의 실행 상태와 독립적이다. SQL Server는 원본 저장소이고 Qdrant는 향후 재생성할 수 있는 인덱스로 사용한다.
- Next.js가 SQL Server의 `appdb`에 `records`, `schedules`, `tasks`, `task_transitions` 초기 스키마를 적용한다.
- 현재 API 계약과 입력 규칙은 [API.md](API.md)에 정리했다.
- 구현된 SQL Server 테이블과 관계는 [ERD.md](ERD.md)에 정리했다.

## 전환 전 검증 이력
- 사용자 요청으로 `docker compose stop`을 실행했다. `docker compose ps -a`에서 백엔드와 MySQL을 포함한 6개 컨테이너가 모두 `Exited` 상태인 것을 확인했다.
- 2026-11-20 Docker 점검에서 프론트 Vite가 먼저 기동해 Spring Boot가 포트를 열기 전 API 요청에 `ECONNREFUSED`가 발생한 것을 로그 시각으로 확인했다. 기동 완료 후 6개 컨테이너가 실행 중이고 MySQL은 `healthy`였다. Flyway 마이그레이션 3개 검증을 통과했으며 기록·약속·할 일·대시보드 조회는 백엔드 직접 및 프론트 프록시 경유 모두 HTTP 200을 반환했다. FastAPI, Qdrant, Ollama 상태 요청과 `docker compose config --quiet`도 통과했다. 부팅 순서 개선이 필요하면 백엔드 준비 상태를 확인한 뒤 프론트를 시작하도록 Compose를 조정한다.

- 주간 그래프 제목을 **남은 일정**, **지난 일정**으로 변경한 뒤 프론트 lint와 build를 통과했다.

- 포트 변경 후 현재 상태를 재확인했다. 6개 컨테이너가 실행 중이고 MySQL은 `healthy`였다. 프론트 홈, 프론트 경유 및 백엔드 직접 기록 조회, FastAPI `/health`, Qdrant `/readyz`, Ollama `/api/tags`가 모두 HTTP 200을 반환했다.

- Windows TCP 예약 범위 `7945–8044`, `8054–8153`에 포함된 AI·백엔드 호스트 포트 `8000`, `8080`을 각각 `18000`, `18080`으로 변경했다. Compose 내부 포트는 AI `8000`, 백엔드 `8080`이다. `docker compose config --quiet`와 `docker compose up -d`가 성공했고 6개 컨테이너의 실행 및 MySQL `healthy`를 확인했다. 프론트 홈, 프론트 경유 및 백엔드 직접 기록 조회, FastAPI `/health`, Qdrant `/readyz`는 HTTP 200을 반환했다.

- 홈 로고의 아이콘 안에 있던 글자를 제거했다.
