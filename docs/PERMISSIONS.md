# 권한 체계

최종 정리: 2026-11-23 (Asia/Seoul)

사용자와 합의한 **목표 권한**이다. 아래 "지금 구현과 다른 점"의 항목은 아직 코드에 반영하지 않았다. 구현 이력은 [HANDOFF.md](HANDOFF.md), 남은 작업은 [REMAINING_WORK.md](REMAINING_WORK.md)에 있다.

## 원칙

- 권한은 **직급**으로 정한다. 별도의 '관리자' 권한 표시는 두지 않는다.
- **대표·본부장**은 회사 전체를 관리하고, **팀장**은 자기 팀의 관리자다. 팀장은 다른 팀을 읽기만 한다.
- 다른 팀의 업무 일정은 누구도 직접 고치지 않는다(읽기 전용).
- 개인 공간은 본인만 본다. 대표·본부장도 볼 수 없다.

## 직급과 인원

| 직급 | 인원 | 정하는 방법 |
|---|---|---|
| 대표 | 회사 전체 1명 | 가입할 때 본인이 고름(이미 있으면 고를 수 없음) |
| 본부장 | 회사 전체 1명 | 가입할 때 본인이 고름(이미 있으면 고를 수 없음) |
| 팀장 | 팀마다 1명 | 팀장으로 초대받은 사람만. 대표·본부장이 조직 관리에서 지정 가능 |
| 프로 | 제한 없음 | 기본값 |

- 한 사람은 한 팀에 속한다. 대표·본부장도 소속 팀이 있다(예: 경영지원팀).
- 처음 설치할 때 첫 사용자는 **대표 또는 본부장**으로 시작한다. 조직 전체를 관리할 사람이 있어야 다른 팀 팀장을 초대할 수 있기 때문이다.

## 아직 정하지 않은 것

| 항목 | 선택지 | 추천 |
|---|---|---|
| 회의 보고서 결재 흐름 | 1단계(팀장이나 대표·본부장 중 한 명이 결재하면 완료) / 2단계(팀장 결재 → 대표·본부장 최종 승인) | 2단계. 위 권한표의 '최종 승인'은 2단계를 가정했다 |
| 팀장이 자기 팀원 직급을 고칠 수 있는지 | 대표·본부장만 / 팀장도 자기 팀 프로에 한해 | 대표·본부장만 |
| 대표·본부장 자가 선택 | 지금처럼 가입 때 본인이 고름 / 기존 대표·본부장의 승인 | 처음 1명 이후에는 대표·본부장이 조직 관리에서 지정 |
| 변경 이력 | 조직 변경(팀장 지정·팀 이동·직급 수정)을 누가 언제 했는지 남길지 | 남김(3단계 업무 변경 이력과 함께) |
