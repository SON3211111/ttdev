# MEMORIA 단계별 개발 계획

기준: 2026-11-16~11-27, 평일 10일 × 8시간 = 80시간. 11/21~22 주말은 제외한다.

계획 시간은 추정치이며 실제 코드·환경 점검 후 조정한다. 2026-11-16에 0단계 통과. 2026-11-17에 최소 설계와 사용자 정책 동의로 1단계 완료. 이후 메모 DB/API/화면 연결 및 검증으로 2단계 완료(`STAGE2_CHECK.md`). 2026-11-17에 3단계 일기 CRUD·통합 목록·검색 구현과 검증을 완료했다(HANDOFF.md 최신 절). 2026-11-17에 4단계 일정 DB/API/화면 및 검증을 완료했다(`STAGE4_CHECK.md`). 5단계 이후는 미완료다. 환경 검증 이력은 `ENVIRONMENT_CHECK.md`에 기록한다.

2026-11-17 사전 정리: 환경·최소 설계의 계획 예산을 각각 4시간으로 배분해 단계 합계를 80시간에 맞췄다. 납기와 마지막 검증·문서화 16시간은 유지한다. 이는 계획 예산의 정리이며 실제 소요 시간이나 남은 시간을 뜻하지 않는다. 1단계의 실제 완료일은 11/17로 당초 계획일 11/16과 다르다.

## 0단계 — 환경 동작 확인 (계획 4시간, 11/16)

- Docker 서비스 상태·연결 확인.
- 프론트→Spring Boot→MySQL, Spring Boot→FastAPI 확인.
- 샘플 임베딩→Qdrant 저장/검색→LLM 응답 확인.
- 재시작 후 DB 데이터 유지 확인.

완료: 서비스 간 테스트 요청과 AI 샘플 처리가 성공한다. 설정 파일 존재만으로 통과시키지 않는다. 모델 메모리·실행 문제가 있으면 우선 해결한다.

## 1단계 — 최소 설계 (계획 4시간, 11/16 / 실제 완료 11/17)

- Record/Schedule 필드·관계·필수값·길이·삭제 방식.
- 기록 날짜/작성 시각과 한국 시간 처리 정책.
- DB 스키마 변경 관리 방법.
- 첫 기능 API 요청/응답·공통 오류 형식.
- 홈·작성·목록·상세의 간단한 화면 흐름.

완료: 프론트·백엔드가 동일한 계약으로 구현 가능하다. 필요한 ERD·API 예시·와이어프레임·완료 체크리스트를 간단히 남긴다. 전체 문서 완성을 기다리지 않는다.

## 2단계 — 빠른 메모 (8시간, 11/17)

1. 기록 테이블.
2. 등록·목록·상세 API.
3. 수정·삭제 API.
4. 홈 입력창과 목록/상세/수정 화면.
5. 입력 검증·저장 중·실패 상태.

완료: 화면 저장→새로고침 유지, 수정 반영, 삭제 제외, 빈 본문 거부. 첫 번째 DB/API/UI 통합 기능이다.

## 3단계 — 일기·기록 목록 (8시간, 11/18)

- 일기 작성(날짜·본문·선택 제목) 및 CRUD.
- 통합 목록, 전체/일기/메모 필터.
- 제목·본문 키워드 검색: 구현 후 2026-11-17 사용자 요청으로 UI/API 제거. 현재 범위에서 제외한다.
- 날짜순 정렬·기본 페이지 처리.

완료: 두 기록을 구분해 작성하고 통합 목록에서 조회한다. 일반 검색 UI/API는 사용자 요청으로 범위에서 제외했다.

## 4단계 — 일정 관리 (8시간, 11/19)

- 일정 테이블·CRUD API·화면.
- 선택 시간/장소/메모, 예정/완료/취소.
- 오늘부터 향후 7일 예정 일정 목록.

완료: 시간 미정 저장, 수정·상태·삭제 반영. AI 없이 일정 관리 가능.

## 5단계 — 통합 캘린더 (8시간, 11/20)

- 월간 캘린더·월 이동·오늘 이동.
- 월 단위 조회·종류별 표시·선택 날짜 목록.
- 선택 날짜로 기록/일정 작성.
- 날짜 변경·삭제 후 갱신.

완료: 날짜에서 기록·일정을 열고 추가한다. **1주차 말에는 AI 없이 기본 서비스가 동작한다.**

## 6단계 — AI 검색 데이터 준비 (8시간, 11/23)

- 청크 규칙·임베딩·Qdrant 저장.
- 원문 ID/버전/날짜와 처리 상태.
- 수정 인덱스 갱신·삭제 제거.
- 실패 재처리 경로.
- 이전 버전·삭제 기록의 원문 검증.

완료: 등록·수정·삭제가 검색에 반영되고 임베딩 실패 중에도 원문은 보존된다.

## 7단계 — AI 기억 검색 (8시간, 11/24)

- 질문 API·화면.
- 키워드/의미 후보·중복 제거·유효 원문 확인.
- 근거 답변·종류/날짜/문장/원문 링크.
- 결과 없음·타임아웃·AI 장애.

완료: 질문→관련 기록→답변→원문 확인. 잘못된 출처나 근거 부족 응답도 점검한다.

## 8단계 — AI 약속 준비 (8시간, 11/25)

- 일정 상세 버튼·일정 정보 기반 검색.
- 관련 기억/준비사항/누락 정보 응답 구조.
- 사실/제안 구분·항목별 근거.
- 기록 없음·오래된 정보·요청 중/실패/재시도.

완료: 실제 일정에서 결과와 출처 확인. 7단계 검색·출처 구조를 재사용한다. **이후 새 기능 추가 중단.**

## 9단계 — 통합 검증·수정 (8시간, 11/26)

- 기록/일정/캘린더 전체 흐름.
- 월 경계·날짜 변경.
- 수정·삭제 후 재검색.
- AI 중단 중 저장/조회.
- 가상 기록 30개·검색 질문 20개·준비 사례 5개 평가.
- 동명이인·오래된 정보·기록 없음 확인.

완료: 핵심 흐름을 막는 결함이 없고 평가 결과·한계가 기록된다. 기획서의 평가 목표를 참고한다.

## 10단계 — 실행·문서·시연 (8시간, 11/27)

- Docker 재시작과 데이터 유지.
- 설치·환경변수·실행 절차 검증.
- README·API 문서·가상 시연 데이터.
- 알려진 한계·남은 결함 수정.

최종 시연: 메모 저장→일기 작성→일정 등록→캘린더→AI 검색→AI 약속 준비→출처.

## 지연 대응

화면 꾸밈·캘린더 상세 표시·AI 제안 다양성을 먼저 줄인다. 원문 보존·출처·수정/삭제 반영·장애 처리는 유지한다. 필수 기능 미완성 시 상태를 명시하고 시간을 재산정한다. 테스트 기간을 새 기능으로 소진하지 않는다.

## 후속 대화의 진행 기록

각 단계 완료 시 HANDOFF.md에 변경 파일·실행한 검증·결과·남은 문제·다음 단계 기록. 예정 작업과 실제 완료를 혼동하지 않는다.
